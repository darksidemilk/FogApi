# builders/ — the Python client's build stages

Empty until the Python client exists. The shape mirrors `pwsh/builders/`:

```
builders/
  buildFunctions.psm1   or a Python/Make equivalent -- one function per stage
  make.ps1              this client's orchestrator
```

The root `make.ps1` / `make.sh` discover a client by looking for
`builders/make.ps1`. Until this directory has one, `./make.ps1 -Client python`
reports that python is scaffolding, and `-Client all` skips it by name rather
than failing.

## What the stages will be

Not necessarily the same list as `pwsh`. The pwsh client compiles C#, so it has
a Compile stage and an artifact check that exists because AutoRest's
`build-module.ps1` exits 0 on failure. A Python client generated by
openapi-generator has no compile step and different packaging.

What both clients share is upstream of them: `spec/` — one snapshot, one
provenance record, one set of document fixes. Every defect found getting the
PowerShell client to build was a defect in the document, and each would have
broken a Python client identically:

- a bare top-level array response cannot be modelled
- `multipart/form-data` may not be generatable at all
- `servers[0].url` is baked in, so a client learns its server from the
  document it was generated from

Read `spec/generators/README.md` before starting, and add this client's
generator config beside `spec/generators/autorest-readme.md` rather than here —
generator configs live with the spec, orchestration lives with the client.
